# 教材APKGの検証

検証日：2026-10-15。

## 自動検査

```sh
mise exec -- npm run ci
```

Vitestでは生成されたZIPとSQLiteを実際に開き、モデル・GUID・フィールド・音声バイト列・空の履歴・再現性・入力拒否・上書き保護を調べる。writerをmockした検査ではない。

ビルド済みCLI単独の確認は、先に`mise exec -- npm run build:packages`、続けて`mise exec -- npm run test:content`。JSON出力、再生成の一致、既存出力の保護、public出力でのprivate入力拒否を確認する。GitHub ActionsはUbuntuとWindowsでこの検査を実行する。CIはAnki本体でのimportを実行しない。

## Anki標準import処理での確認

Windows上のAnki 26.9.3 coreを使い、空の使い捨てコレクションに自作fixtureをimportした。通常のprofileや既存の個人コレクションは使っていない。Ankiの標準package importerとschedulerを呼び出す検証であり、GUI操作・音声の実再生・AnkiMobile・AnkiDroidの検証ではない。

| 操作                                            | 確認結果                                                      |
| ----------------------------------------------- | ------------------------------------------------------------- |
| 無関係なBasicノート1件を作成して初回import      | 教材4ノート・4カード・音声1件が追加され、合計5ノート・5カード |
| 同じ版を再import                                | 重複なし。利用者側のnote/card IDを維持                        |
| 専用モデルを確認                                | フィールドとテンプレートの固定IDを認識                        |
| 1カードをAnkiのschedulerで回答                  | 学習状態と復習履歴1件を作成                                   |
| 学習者がCSSと別のノート本文を編集し、教材を更新 | より新しい学習者の本文編集とCSSを保持。他の本文と音声を更新   |
| 学習者の編集より新しい教材版をimport            | Anki標準の規則で配布側の本文へ更新                            |
| 各更新後に学習情報を比較                        | カードID・学習予定・回答回数などと復習履歴を維持              |
| 音声を変更してimport                            | Anki内の音声が元のバイト列と一致。missing mediaは0            |
| 古い版を再import                                | 新しい本文を巻き戻さず、無関係なノートも維持                  |

変更時刻を制御して「古い配布版 < 学習者の編集 < 新しい配布版」の両方向を確認した。学習者の編集を常に残す保証ではない。モデル構成やimport設定を任意に変更した場合の全組み合わせは対象外。

この検証用のAnki/Python環境は製品・通常の開発環境・CIの依存関係に追加していない。

## GUI・端末で再確認するとき

1. Ankiで専用の空profileを作り、Anki版とpackage import設定を記録する。
2. [コマンド例](../reference/content-apkg.md)で自作fixtureのAPKGを生成し、通常のデッキpackageとしてimportする。
3. 4ノート・4カード、表裏の文字、音声の再生、出典、配布条件を確認する。合図音は発音見本ではない。
4. 同じ版を再importし、ノート・カードが増えないことを確認する。
5. 一部を復習し、別の本文やCSSを編集する。学習予定・履歴・編集時刻を控える。
6. 教材IDを維持したまま本文・音声を改訂し、revisionと変更時刻を進めて生成する。学習者の編集より前・後の時刻で更新結果を比較する。
7. 更新後もカードID・学習予定・履歴が保たれ、missing mediaがなく、無関係なノートに変化がないことを確認する。

再現結果を記録するときは、Anki版、import設定、教材の改訂・変更時刻、モデル構成の変更有無を含める。個人profileや私的な教材・履歴を共有しない。
